# Audit of CurseTerm, BarrierKit and their integration

Date: 2026-11-07. Read-only audit: it changes no code. The
fixes come separately, once they are approved.

## Goal and scope

Review everything related to CurseTerm: the app, BarrierKit (`barrier-kit`,
`vow-design`, `vow-appearance`, `infinity-protocol`), its integration in
Malaysia and its arrival in dotfiles. The scope starts at the code of the
four repos and ends at the Nix package that the system installs.

The criteria are the rules of the `AGENTS.md` files of the four repos
(«Código mínimo» 1–10, bilingual docs, tokens, Fluent, Super shortcuts,
nothing tested without running it) and the behaviour of iTerm2.

## Reader

Whoever maintains CurseTerm and BarrierKit and approves the list of
fixes.

2. Phase 1, the basics: compilation, dependencies, rules, i18n and docs.
3. Phase 2, CurseTerm module by module.
4. Phase 3, parity with iTerm2.
5. Phase 4, security.

7. Phase 6, BarrierKit in depth.
8. Phase 7, packaging and installation.

reviews. The most serious items were checked again by hand or in the lab; the
«verified?» column says how: «Yes, executed» means reproduced; «Yes» or
«code» means read end to end without running it.

## 4. Root causes of BK-047 and BK-017

They come from reading the code of freya 0.4.3 and of the kit; they have not been reproduced
with an animation on screen.

### Root cause of BK-047 (the `freya-animation` animations get no frames)

#### How Freya 0.4.3 schedules an animation tick

1. `use_animation*` registers an `Effect::create_sync_with_gen` (`fa/hook.rs:445`). When its dependency changes, the effect **does not run inline**. It runs as a *task*: `rx.notified().await` and then `callback(gen)` (`fc/lifecycle/effect.rs:31-41`). That callback calls `UseAnimation::run` (`fa/hook.rs:453-456`).
2. `run()` does `spawn(async { platform.send(RequestRedraw); loop { ticker.tick().await; platform.send(RequestRedraw); …advance… } })` (`fa/hook.rs:256-319`). `spawn` only queues `Message::PollTask` on the `Runner` channel (`fc/lifecycle/task.rs:40-57`).
3. `RenderingTicker::tick` waits on an `async_watch` (`fc/rendering_ticker.rs:22-24`). The task waker queues `PollTask` again.
4. `Runner::handle_events` (`fc/runner.rs:565-627`) has three behaviours:
   - It returns `Ready` **as soon as there are `dirty_scopes`**, without polling the pending tasks (`:578`, `:612`).
   - It polls `dirty_tasks` only if there are no dirty scopes.
   - Otherwise, it enters `while let Some(msg) = self.receiver.next().await` (`:616-625`). That loop **moves `MarkScopeAsDirty`/`PollTask` to `dirty_scopes`/`dirty_tasks` and returns `Pending`**.
5. `sync_and_update` → `handle_events_immediately` does not poll tasks either if there are dirty scopes (`fc/runner.rs:643-645`).
6. The official runner (freya-winit) covers both cases:
   - After each poll it **always** calls `sync_and_update` (`fw/renderer.rs:480`).
   - If the poll returned `Ready`, `PollRunner` is queued again (`fw/renderer.rs:460-468`).
   - `RequestRedraw` → `request_redraw` (`:527-529`), and the ticker is sent after painting (`:879`).

#### What the kit does

- `AppInstance::poll` (`app.rs:236-267`) polls `handle_events()` once. It returns `true` only if the future returned `Ready` or input events arrived.
- `Runtime::poll_all` calls `update()` (→ `sync_and_update`) **only if `poll()` returned `true`** (`runtime.rs:442`). `settle_sized_reactions` does the same (`app.rs:357`).
- After a `Ready` the kit does not poll again: there is no equivalent of the re-queued `PollRunner`.
- It does send the ticker after `present` (`surface.rs:242`). `RequestRedraw` does produce a frame even if the tree does not change (`runtime.rs:175-178` → `redraw_all` → `surface.rs:358-366`). That is why the API proposed in `barrierkit-gaps.md` («que `RequestRedraw` produzca un fotograma», that `RequestRedraw` produces a frame) **is not the cause**.

#### The chain that hangs (a `State<bool>` change without moving the mouse)

1. The `State` is written → `PollTask(efecto)`.
2. Ping → `poll()`. The effect runs inside `handle_events`:
   - `animated_value.set` → `MarkScopeAsDirty(componente)`.
   - `spawn` → `PollTask(animación)`.
3. The inner loop (`fc/runner.rs:616-625`) drains those messages into `dirty_scopes`/`dirty_tasks`, and the future returns `Pending`.
4. `poll()` returns `false` and `update()` is not called (`runtime.rs:442`). No ping is left pending, because the channel waker was already consumed before those sends. Nobody polls the animation task, so nobody sends `RequestRedraw`.
5. Everything stays frozen until the next event.
6. When it arrives, `prev_frame.elapsed()` accumulates all the idle time (`fa/hook.rs:280-283`) and the animation **jumps to the end**: that is exactly the BK-047 symptom.

The same loss repeats when a `poll` returns `Ready` early: the tasks just woken (tick after `ticker_sender.send`) stay in `dirty_tasks`. If that `update()` produces no mutations (e.g. the first step with `index≈0`), there is no frame, no `settle` and no poll.

#### Minimal fix (same as freya-winit)

```rust
// app.rs — poll(): un Ready significa que hay más trabajo; volver a hacer poll
if ready { self.waker.wake_by_ref(); }

// runtime.rs:442 — sincronizar siempre, como fw/renderer.rs:480
window.app.poll();
if window.app.update() { window.needs_redraw = true; }

// app.rs:357 — igual en settle_sized_reactions
self.poll();
if !self.update() { return; }
```

- `update()` without mutations is cheap: `sync_and_update` with the empty set.
- With this, `accessibility_pending()` is no longer needed in `poll_all`, because `update()` already consumes the AT-SPI actions.
- The kit itself also suffers from it: `animation.rs:21` (`use_switch_progress`) uses `use_animation_transition`.

### Root cause of BK-017 (menu handlers outside the Freya context)

#### Required context

- All the Freya context API goes through `CurrentContext::with`, which does `expect("Your trying to access Freya's current context outside of it…")` (`fc/current_context.rs:55-57`).
- That context only exists inside `CurrentContext::run`/`run_with_reactive`, that is, in `Runner::{handle_event, handle_events, sync_and_update, run_in}`.
- On it depend `consume_root_context`, **including `try_consume_root_context`** (`fc/lifecycle/context.rs:56-77`), `spawn`, `Clipboard::set` (`freya-clipboard/src/clipboard.rs:33,47`), `Timers::get`, `WindowControls::get`, `Popups::get` and `Platform::get`.

#### Where the kit invokes app code without entering the runner

1. **Keyboard shortcut:** `KeyboardHandler::press_key` → `Runtime::key_event` → `self.surfaces[idx].app.menu_actions.dispatch(action_id)` (`input/seat.rs:458-460`). It is a Wayland dispatch callback inside calloop, without `run_in`.
2. **Global menu (dbusmenu) and StatusNotifierItem:**
   - The `barrier-dbusmenu` thread (`app_menu/server.rs:45-48`) receives `Event` → `handle.push_action` + `wake.wake()`.
   - That reaches the *wake ping* source (`runtime.rs:235-244`) → `process_menu_actions` → `surface.app.menu_actions.dispatch(&id)` (`app_menu_export.rs:40-51`).
   - The right thread, but outside the context.
3. **`org.freedesktop.Application.ActivateAction`:** the `Timers::wakeup` callback (`app/application.rs:36-53`) calls `menu_actions.dispatch` from the wake source (`runtime.rs:236-239`).
4. Equally exposed, although they are not menus:
   - `Timers::after` callbacks (`timer.rs:72-79`).
   - `Timers::wakeup` callbacks (`runtime.rs:236-239`).
   - `PopupSpec::on_dismissed` (`popup.rs:495-499`).

None of these points goes through `Runner::run_in`. Until the next `poll()`, the thread's `CurrentContext` is empty (`fc/current_context.rs:45-52` clears it on exit).

#### Proposed fix

1. Add `AppInstance::run_in(&self, f) { self.runner.run_in(f) }` (`fc/runner.rs:758-769`, context of the ROOT scope) and wrap with it:
   - `seat.rs:459`;
   - `app_menu_export.rs:49`;
   - the `on_dismissed` of `popup.rs:498`, with the runner of the `owner`.
2. Give `Timers` an `owner: ObjectId`, as `Popups` already has (`app.rs:86-97`). Store `(owner, callback)` in `TimerQueue`/`WakeQueue`. On firing, look up the surface and run `surface.app.run_in(callback)`. If the surface no longer exists, drop the callback (and in `wakeup`, remove it).
3. Point 2 also covers `application.rs:51` and closes BK-032 without `use_alive`.
4. Warning: `CurrentContext::run` does not restore a previous context (`fc/current_context.rs:45-52`). `run_in` must not be nested.

## 8. What could not be verified and why

### Environment

- **IME:** there is no `vime` helper in this environment and no
  `zwp_input_method_v2` client; preedit was not tested.
- **Moving a session to another window and the global menu:** without a D-Bus
  session bus in the lab (`barrier-dbusmenu: no session bus`), the menu is only
  local and cannot be triggered from outside; not tested.
- **BK-047 on screen:** the root cause comes from reading; no animation
  was recorded.
- **Real 60 Hz display, real GPU and Malaysia:** the lab is sway
  with lavapipe; neither `./dev.sh demo` nor Malaysia's `lab` was run.
- **dotfiles:** evaluating `keel-x86_64-linux` requires building the whole of Malaysia
  during evaluation (IFD from `system.replaceDependencies` in
  `nix/malaysia.nix`), and its Cargo git dependencies clash with the proxy CA
  in the sandbox; see the baseline.
- **Disk:** the session space ran out halfway through phase 0 (a 6.5 GB Nix git
  cache); the cache and the `target/*/incremental` directories were deleted and the
  builds were repeated.

### Read-only reviews

#### Security

- **Decompression bombs in Skia:** `Image::from_encoded` decodes lazily. It has not been checked what freya-engine/Skia does with a 100 000 × 100 000 PNG when drawing it: whether it fails cleanly or aborts.
- **ssh and raw mode (SEC-04 a):** that the local pty stays without ECHO inside `ssh` is the known behaviour of `ssh -t`, but it has not been run here.
- **`xdg-open` and `.desktop` or executable files:** it has not been checked whether GNOME and KDE run a `file:///…/x.desktop` opened from OSC 8 or from Semantic History, or only open it in an editor.
- **Markup in the notification body (SEC-15):** it depends on the server (GNOME Shell filters almost everything; KDE accepts `<a>` and `<img>`). Not tested.
- **OSC 7 in iTerm2 (SEC-14):** the place where iTerm2 decides whether a remote `currentDir` is valid for local tabs has not been located in `/home/user/iterm2`. The divergence is likely, but not confirmed.
- **Real duration of the SEC-01 block:** it depends on the cost of `Term::linefeed` with a full scrollback. It has not been measured because `cargo` cannot be run.
- **freya text cache with the revealed password (SEC-10.1):** it has not been traced down to the Skia layout.
- **`tracing` destination:** `barrier_kit::logging::init_tracing` shows no write to a file in what was read (`logging.rs:4-16`). It is assumed to go to stderr.
